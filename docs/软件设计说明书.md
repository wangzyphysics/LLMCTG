# LLM中文文本生成系统软件设计说明书

## 1 文档目的

本文说明 LLM中文文本生成系统 V1.0 的总体结构、主要模块、数据流程、接口约束和异常处理策略，为开发维护、测试验收和软件著作权登记提供技术依据。

## 2 系统目标

系统面向需要批量制作分级中文阅读材料的教师、编辑和研究人员。用户指定主题、目标学段、关键词及附加要求后，系统调用离线模板或本地语言模型生成文章，再从篇章结构、长度、目标等级匹配度、重复片段、英文比例和非常用字比例等维度计算质量结果，并输出 JSONL、CSV、JSON 和 HTML 报告。

## 3 总体架构

系统采用分层结构。命令行层负责解析参数和反馈执行结果；业务编排层负责生成、评估、批处理与断点续作；生成器层通过统一抽象支持模板后端与本地 Transformers 后端；评估层完成统计和规则评分；数据层负责 UTF-8 文件读写、格式校验和结构化报告导出。

核心调用链为：用户命令 → 配置加载 → 请求校验 → 内容生成 → 文本规范化 → 可读性评估 → 结果持久化 → 汇总报告。各环节只通过数据对象传递信息，避免脚本间依赖全局变量。

## 4 功能模块

### 4.1 配置管理

配置管理支持默认配置和 JSON 文件覆盖。生成参数包括后端、模型目录、设备、采样温度、Top P、Top K、重复惩罚和各等级最大生成长度；评估参数包括通过分数、质量等级边界、目标句长和异常比例阈值。

### 4.2 请求模型

生成请求包含主题、阅读等级、附加指令、关键词、数量和随机种子。系统接受英文等级名、数字标签和中文别名，并统一转换为枚举。主题不能为空，单次生成量限制为 1 至 20，防止误操作造成资源占用。

### 4.3 内容生成

模板生成器不依赖第三方组件，主要用于安装验收、演示和业务降级。它根据目标学段选择不同句式、论证深度和篇章结构，并支持固定随机种子复现结果。

本地模型生成器在第一次调用时惰性导入并加载 PyTorch 与 Transformers。系统禁止执行模型仓库中的远程代码，自动选择 CPU 或 CUDA，按学段控制最大新令牌数，并只解码模型新增部分，避免把提示词重复写入文章。

### 4.4 质量评估

评估器统计总字符数、汉字数、句数、段落数、平均句长、最大句长、字形多样性和标点比例。难度预测综合平均句长、非常用字比例和超长句惩罚。综合分由结构、长度、等级匹配和流畅性四部分加权得到，并生成警告与修改建议。

该评估为工程质量筛查，不替代专业教育测量。最终公开或教学使用前仍应由具备相应知识的人员审核事实准确性、价值适宜性和年龄适配性。

### 4.5 批处理与报告

批处理逐行读取 JSONL，单条任务失败时写入错误文件并继续后续任务。输出包括完整文章记录、错误记录、汇总 JSON、适合表格查看的 CSV 和可直接在浏览器打开的 HTML 报告。已有结果可按稳定任务编号跳过，实现基础断点续作。

## 5 数据设计

输入任务字段包括 `topic`、`level`、`instruction`、`keywords`、`count` 和 `seed`。其中主题必填，其余字段可使用默认值。输出文章记录包含请求编号、主题、等级、标题、正文、生成后端、生成时间和评估结果。

稳定编号由主题、等级、随机种子、序号和正文摘要计算，不包含用户路径或设备信息。结构化文件采用 UTF-8；CSV 使用 UTF-8 BOM，以提高中文办公软件兼容性。

## 6 异常与安全设计

配置不存在、等级非法、数量越界、输入 JSON 格式错误和模型依赖缺失时，命令行返回明确的中文错误信息与非零状态码。批处理隔离单条业务异常，并在日志中保留堆栈供维护人员定位。

默认模板后端不访问网络。本地模型后端只读取用户指定目录，并设置 `trust_remote_code=False`。系统不会把输入文章上传至远程服务。输出文件由用户指定位置，文件名与内容写入使用安全编码。

## 7 可维护性设计

业务数据使用带类型标注的数据类；生成后端实现统一抽象；配置、文本处理、输入输出、评估、报告和命令行职责分离。自动化测试覆盖等级解析、文本规范化、评分边界、生成流程、错误隔离和报告产出。

## 8 运行环境

基础功能要求 Python 3.10 及以上，不要求网络和 GPU。本地大模型模式需要 PyTorch、Transformers、PEFT 及与模型匹配的硬件资源。Windows、Linux 和 macOS 均可运行，命令示例以 Windows PowerShell 和通用 Shell 为主。
